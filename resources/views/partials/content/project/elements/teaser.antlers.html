{{# content/project/elements/teaser — a single teaser on the portfolio listing. Rendered inside a {{ projects }} loop, so `title`, `url`, `client` and `teaser` are read straight from the entry. Only the layout of the frame is passed in; the placement on the grid is the caller's job. Params: image (required unless video) asset shown in the frame video (optional) teaser video (mp4), takes precedence ratio (required) responsive aspect-ratio classes for the frame crop (required unless video) the frame's width/height below md, as a number crop_md (required unless video) the same from md up sizes (required unless video) the frame's rendered width, for the browser to pick a candidate from srcset frame (optional) extra classes for the frame, e.g. a bleed heading_level (optional) `h3` where the surrounding block already has the h2, as the grid block does; the listing keeps the default h2 The global `h3` rule in components/headings.css adds a bottom margin; `mb-0` takes it off again, so both levels look the same. One link wraps the whole tile, the way the competency tiles do it (`partials/fieldsets/teaser/competencies/item.antlers.html`). Frame, title, client and arrow all lead to the same project, so three separate anchors would only repeat the same destination three times in the tab order. The arrow is a plain icon inside that link, not a link of its own. Only the frame bleeds past the container — the caption stays on its column, the way the design keeps the Kriens teaser's text at the left margin while its image runs off the page. The caption reads client, then title, then the teaser line. The client sits above the title as a small eyebrow; the teaser below it carries the type the client line used to have. The image is cut to the frame's proportions by Glide (`crop_focal`, so a focal point set on the asset decides the crop) rather than by `object-cover` in the browser. Otherwise a phone would download a whole 3:2 image to show a square out of it. `crop` and `crop_md` repeat the two ratios in `ratio` as numbers, because Glide cannot read a Tailwind class. Each ratio comes in several widths; the browser picks one from `sizes` and the screen's pixel density. Nothing is generated until a browser asks for it (Glide's cache is off), so unused widths cost nothing. Older browsers without WebP get one JPEG. A teaser video only gets its source about a screen before it scrolls into view (data-video-lazy, modules/video.js). `autoplay` alone would ignore `preload="none"` and download every teaser video on arrival. Every project entry carries its own teaser (docs/redaktionsstandard.md). If one is empty, the line stays empty; there is no stock sentence to fall back on. #}}
